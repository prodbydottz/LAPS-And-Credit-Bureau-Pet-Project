# LAPS-001. Обработка кредитной заявки при недоступности Кредитного бюро

> Учебный пет-проект.
> Все названия систем, идентификаторы, API-endpoint'ы, данные, статусы и бизнес-правила являются учебными и не относятся к реальным системам или процессам банка.

---

## 1. Описание проекта

Проект моделирует доработку процесса обработки кредитной заявки в системе **LAPS** при временной технической недоступности внешнего Кредитного бюро.

В исходном процессе техническая ошибка или отсутствие ответа от Кредитного бюро могли приводить к автоматическому отказу по заявке. Это создаёт риск необоснованного отказа клиенту, негативного клиентского опыта и дополнительных обращений в поддержку.

Целевой процесс исключает автоматический отказ из-за технической ошибки внешней системы.

Если Кредитное бюро недоступно, LAPS выполняет до трёх попыток обращения, включая первоначальный запрос. Если успешный ответ не получен после третьей попытки, заявка переводится в статус `MANUAL_REVIEW`, создаётся задача кредитному менеджеру, а клиент получает уведомление в мобильном приложении.

---

## 2. Бизнес-проблема

При обработке кредитной заявки LAPS получает данные из внешнего Кредитного бюро.

Если внешний сервис возвращает техническую ошибку (`502`, `503`, `504`) или не отвечает в течение установленного timeout, автоматическое решение по заявке не может быть принято корректно.

Техническая недоступность внешнего Кредитного бюро не должна быть причиной автоматического отказа клиенту.

---

## 3. Цель доработки

Исключить автоматический отказ по кредитной заявке в случае временной технической недоступности Кредитного бюро.

Обеспечить контролируемую обработку заявок:

1. LAPS отправляет запрос в Кредитное бюро.
2. При технической ошибке или timeout фиксируется ошибка интеграции.
3. LAPS выполняет не более трёх попыток обращения, включая первоначальный запрос.
4. Между повторными запросами выдерживается интервал 30 секунд.
5. После третьей неуспешной попытки заявка переводится в `MANUAL_REVIEW`.
6. Создаётся задача кредитному менеджеру.
7. Клиент получает нейтральный статус о дополнительном рассмотрении.
8. Технические причины ошибки не отображаются клиенту.

---

## 4. Основные решения

| Область | Решение |
|---|---|
| Обработка ошибок бюро | `502`, `503`, `504` и timeout не приводят к автоматическому `REJECTED` |
| Retry-механизм | Не более трёх обращений к Кредитному бюро, включая первоначальный запрос |
| Интервал retry | 30 секунд между повторными попытками |
| Ручное рассмотрение | После исчерпания лимита заявка получает `MANUAL_REVIEW` |
| Причина рассмотрения | `CREDIT_BUREAU_UNAVAILABLE` |
| Задача менеджеру | Создаётся после перевода заявки в `MANUAL_REVIEW` |
| Защита от дублей | Используется заголовок `Idempotency-Key` |
| Сквозная трассировка | Используется заголовок `X-Correlation-ID` |
| Пользовательский интерфейс | MB показывает нейтральный экран без `503`, timeout и технических кодов |
| Уведомления | Клиент получает push-уведомление о дополнительном рассмотрении |

## 5. Статусы заявки

| Статус | Описание |
|---|---|
| `DRAFT` | Заявка создана, но ещё не отправлена на рассмотрение |
| `SUBMITTED` | Заявка принята LAPS |
| `SCORING_IN_PROGRESS` | Выполняется проверка и запрос в Кредитное бюро |
| `APPROVED` | Заявка одобрена |
| `REJECTED` | Заявка отклонена по бизнес-правилу или кредитному решению |
| `MANUAL_REVIEW` | Заявка требует ручного рассмотрения кредитным менеджером |
| `TECHNICAL_ERROR` | Необработанная внутренняя техническая ошибка |

> `REJECTED` используется только как результат бизнесового кредитного решения.  
> Техническая ошибка интеграции с Кредитным бюро не должна автоматически переводить заявку в `REJECTED`.

## 6. Основной сценарий

```text
Клиент отправляет кредитную заявку через MB
        ↓
MB передаёт заявку в LAPS
        ↓
LAPS проверяет Idempotency-Key, валидирует данные и создаёт заявку
        ↓
LAPS возвращает MB: 202 Accepted + applicationId + SUBMITTED
        ↓
LAPS устанавливает статус SCORING_IN_PROGRESS
        ↓
LAPS запрашивает данные в Кредитном бюро
        ↓
Кредитное бюро недоступно / возвращает 503 / наступает timeout
        ↓
LAPS фиксирует ошибку и увеличивает attemptCount
        ↓
Повторный запрос через 30 секунд
        ↓
После третьей неуспешной попытки:
MANUAL_REVIEW
        ↓
Создание задачи кредитному менеджеру
        ↓
Push-уведомление клиенту
        ↓
Клиент открывает уведомление
        ↓
MB получает актуальный статус через GET /loan-applications/{applicationId}
        ↓
Отображается экран «Заявка находится на рассмотрении»
```

## 7. API

### Создание заявки

```http
POST /api/v1/loan-applications
```

Headers:

```http
Authorization: Bearer <access_token>
Idempotency-Key: <uuid>
X-Correlation-ID: <uuid>
Content-Type: application/json
```

Пример request:

```json
{
  "productCode": "CONSUMER_LOAN",
  "requestedAmount": 2500000,
  "termMonths": 24,
  "monthlyIncome": 450000,
  "consents": {
    "personalDataProcessing": true,
    "creditHistoryCheck": true
  }
}
```

Пример response:

```json
{
  "applicationId": "f7c3b6c5-257a-4511-97f3-e9e6a83dd60c",
  "status": "SUBMITTED",
  "createdAt": "2026-09-13T12:00:00+05:00"
}
```

### Получение информации по заявке

```http
GET /api/v1/loan-applications/{applicationId}
```

### Получение текущего статуса заявки

```http
GET /api/v1/loan-applications/{applicationId}/status
```

Полная OpenAPI-спецификация находится в файле:

```text
api/openapi.yaml
```

## 8. Обработка ошибок

| Ситуация | HTTP-код | Error code | Реакция системы |
|---|---:|---|---|
| Не заполнено обязательное поле | `400` | `VALIDATION_ERROR` | MB показывает ошибку у соответствующего поля |
| Клиент не авторизован | `401` | `UNAUTHORIZED` | MB предлагает пройти повторную авторизацию |
| Заявка не найдена | `404` | `APPLICATION_NOT_FOUND` | MB показывает нейтральное сообщение |
| Повторный Idempotency-Key с другим payload | `409` | `IDEMPOTENCY_KEY_REUSED_WITH_DIFFERENT_PAYLOAD` | Новая заявка не создаётся |
| Нарушено бизнес-правило | `422` | `BUSINESS_RULE_VIOLATION` | MB показывает контролируемое сообщение |
| Внутренняя ошибка LAPS | `500` | `INTERNAL_ERROR` | MB показывает нейтральное сообщение |
| Кредитное бюро недоступно после трёх попыток | Не возвращается в MB как `503` | `CREDIT_BUREAU_UNAVAILABLE` | Заявка получает `MANUAL_REVIEW` |

## 11. Ключевые аналитические решения

- Техническая ошибка внешней системы отделена от бизнесового отказа.
- Заявка при недоступности Кредитного бюро не отклоняется автоматически.
- Retry ограничен тремя попытками, включая первоначальный запрос.
- После исчерпания retry заявка переводится в `MANUAL_REVIEW`.
- Для предотвращения дублей создания заявки применяется `Idempotency-Key`.
- Для трассировки межсистемных вызовов применяется `X-Correlation-ID`.
- Клиент не получает технические детали ошибки: HTTP-коды, timeout, `attemptCount`, `correlationId`, `CREDIT_BUREAU_UNAVAILABLE`.
- Кредитный менеджер получает задачу с внутренней причиной и техническим контекстом.
- Все интеграционные ошибки и изменения статуса фиксируются для аудита.
